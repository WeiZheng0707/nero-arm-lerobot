## 2. 本轮代码改动（已提交到工作区）

### 2.1 `src/lerobot/nero_tools/color_detector.py`

| 改动                                                   | 原因                                           |
| ---------------------------------------------------- | -------------------------------------------- |
| `exclude_top_ratio` 参数化（原硬编码 `mask[:int(h*0.28)]=0`） | 0.28 是腕部俯视调的，base 斜俯视会**切掉袋子顶部**。base 用 0.03 |
| `detect_bag()` 增加 `roi` 参数                           | base 视角用 ROI 缩小搜索区，减少棕色桌面误检                  |
| 新增 `normalize_box()`                                 | 统一输出归一化坐标 + 0–1 置信度                          |
| 新增 `detect_scene()`                                  | 一次返回 cube / ball / bag 三个框                   |

**未改** `_shape_name()`：红方块与蓝球靠颜色就能分开，不需要形状判定。

### 2.2 `src/lerobot/nero_tools/episode_capture.py`

| 改动                                                 | 说明                                                                    |
| -------------------------------------------------- | --------------------------------------------------------------------- |
| `--camera-spec NAME=key:value,...` 可重复             | 例：`wrist=serial:xxx,size:640x480,fps:30`；支持 `index:` 与 `serial:` 两种绑定 |
| 保留 `--camera-index` 单相机兼容路径                        | 旧命令不失效                                                                |
| `MultiCamera` 类                                    | 每路一个 reader 线程，`snapshot_all()` 取最新帧快照；**不建队列**（USB 下排队会累积延迟）         |
| `frames/wrist/` + `frames/base/` 双路写盘              | `save_episode` 接受 dict，单相机仍写扁平 `frames/`                              |
| 位置标签**只来自 base**                                   | 腕部相机随臂运动，像素坐标无绝对含义，禁止用于任何标签                                           |
| 帧龄 `host_age_ms()`（主机单调时钟）                         | RealSense 时间戳是**设备时钟**（非 epoch），用 `time.time()-timestamp` 算出的帧龄是错的    |
| 帧龄 > 200 ms → episode 标 `invalid`                  | 冻结的 base 帧会静默污染全部位置标签，不能写成 success                                    |
| 保留 `send_mapped_target()` 内的 `mapper.accept(sent)` | 2026-10-05 修的从臂抖动 bug，**不得回退**                                        |

新增参数：

| 参数                       | 默认   | 用途                                    |
| ------------------------ | ---- | ------------------------------------- |
| `--camera-spec`          | 无    | 声明相机，可重复。第一台是 wrist，名为 `base` 的提供位置标签 |
| `--base-roi X,Y,W,H`     | 无    | base 里检测方块/球的像素区域                     |
| `--base-bag-roi X,Y,W,H` | 无    | base 里检测袋子的像素区域                       |
| `--base-crop X,Y,W,H`    | 无    | 固定裁剪框，目前只记录进 metadata                 |
| `--base-exclude-top`     | 0.03 | base 顶部裁切比例                           |
| `--ball-color`           | blue | 干扰球颜色，`none` 关闭                       |

### 2.3 `src/lerobot/nero_tools/convert_episodes.py`

`observation.environment_state` 从 5 维扩到 **14 维**：

|  idx | 名称           | 说明                    |
| ---: | ------------ | --------------------- |
|  0–3 | cube_x/y/w/h | 红方块框（base 归一化）        |
|    4 | cube_visible | 方块是否检出                |
|  5–8 | bag_x/y/w/h  | **袋子框 —— 袋子移动就体现在这里** |
| 9–12 | ball_x/y/w/h | 蓝球框（A 组恒为 0）          |
|   13 | ball_visible | 蓝球在场 0/1              |

新增 `--image-key CAM=FEATURE`（可重复）支持双图像键；自动识别 `base` / `legacy5` 两种标签格式；缺失对象填 0 不串列。

**为什么球要坐标而不只是 visible**：B-近 组（球距方块 5–10 cm）的训练价值全在“选哪个”。只给 `ball_visible`，模型知道有球但不知在哪，选择能力学不到位。

### 2.4 `tools/realsense_bandwidth_check.py`（新增）

只读带宽/帧率验收工具，不连接机械臂。

- `--list` 列出相机序列号、USB 链路、物理端口
- 默认串行测（单路）
- `--concurrent` **同时打开两台**一起测（唯一诚实的测法，USB 带宽按控制器共享）
- `--strict` 恢复设计文档原始的 p95 < 40 ms 硬门槛

### 2.5 `src/lerobot/motors/nero/read_nero_firmware.py`（安全修复）

**原漏洞**：`--no-enable` 挡不住机械臂通电。

pyAgxArm 的 `connect()` 内部会走 `enable()`，而 `enable()` 是“只发不等”的 fire-and-forget 指令——指令一发出电机就通电。所以标称“只读”的诊断会让机械臂绷紧。

**已修**：

1. 连接成功后明确告警“connect() 自身会唤醒电机”
2. 退出时把只读模式也纳入失能流程，主动失能并回读确认
3. 只有显式 `--no-disable` 才跳过，且会警告“臂可能仍在通电”

## 3. 相机实测结论（已完成）

两台 **Intel RealSense D435i**，固件 5.15.1.55：

| 序列号            | USB | 物理端口               |
| -------------- | --- | ------------------ |
| `261622071323` | 2.1 | `7&9017659&0&0000` |
| `261622078506` | 2.1 | `7&9b83a4c&0&0000` |

**并发测试结果（15 秒）**：

```
base  : 29.34 fps, 27.0 MB/s, p95 47.0ms, max 47.0ms, drops 0 (0.00%)
wrist : 29.01 fps, 26.7 MB/s, p95 47.0ms, max 47.0ms, drops 0 (0.00%)
合计  : 53.8 MB/s
GATE PASSED
```

**关键判断**：

- 合计 53.8 MB/s **超过单条 USB 2.0 实用上限**（35–40 MB/s），说明两台**挂在不同 USB 控制器**上，各占独立总线。这是最优拓扑。
- `drops = 0`：没有任何间隔超过 2 帧周期（66 ms），**一帧都没丢**。
- p95 47 ms 是抖动而非丢帧。原因：串行测只有 26.7 fps、并发测反而 29 fps，同硬件并发不可能更快，说明该数值含 Python 线程唤醒 + 每帧 27 MB/s numpy 拷贝的噪声。

**抖动为什么可接受**：采集器逐帧记录 `age_ms`，转换器按 30 Hz 网格重采样并记录 `max_resampling_error_s`，真正的失效阈值是 **200 ms**。47 ms 远低于此。

**结论：可直接用 640×480@30 双路采集，不需降分辨率。**

可选优化（非阻塞）：确认线是 D435i 原装 USB-C 线、插蓝色 USB3 口、不经 HUB。若 `usb=` 变成 `3.x`，余量更大。

> 相机角色已通过快照确认：`261622078506` 是腕部近景，`261622071323` 是 base 全景。

## 4. 300 条采集方案

### 4.1 为什么袋子必须靠 base 识别

腕部相机随臂运动。`--max-joint-speed 0.6`、臂长 0.6 m 时末端线速度可达 0.36 m/s，30 fps 下单帧位移约 12 mm，在 15 cm 工作距离上对应画面 **30–60 px** 跳动。

**袋子本身已经在动**，再从会跳的视角测它的位置，两个噪声叠加，模型学到的是伪相关。

因此：

- 方块位置、球位置、袋子位置 → **全部只在 base 里检测**
- 腕部只做图像输入 `observation.images.wrist`，**不产生任何位置标签，不裁剪**
- 袋子移动就体现在 `bag_x/bag_y` 随 episode 变化，这是模型学会“袋子在哪”的唯一途径

### 4.2 采集分布

| 组   |      条数 | 场景             | 目的         |
| --- | ------: | -------------- | ---------- |
| A   | **220** | 桌面只有红方块        | 主几何能力      |
| B-远 |  **40** | 蓝球距红方块 > 15 cm | 学会忽略无关物体   |
| B-近 |  **40** | 蓝球距红方块 5–10 cm | **学会精确选择** |
| 合计  | **300** | 全部只夹红方块入袋      |            |

**B-近 的 40 条不能省，也不能凑数。** 如果 80 条球都在远处，模型学不到“哪个才是目标”，真机表现就是抓球。这组成功率最低，**失败就按 D 丢弃，不要为了凑数标成功**。

### 4.3 袋子移动策略

- 每 **20–30 条**移动一次袋子，覆盖约 **5–8 个位置**
- **移动的是袋子，不是相机**。base 支架整个采集期不得移动、不得改曝光/对焦
- 每次移动后确认画面里 base 仍能框到袋子（屏幕显示 `BAG DETECTED`）
- 袋口位置是否全程固定在 5–8 个点内，属未决项，由操作者定

### 4.4 相机安装

| 键       | 安装                                   | 分辨率        | 职责             |
| ------- | ------------------------------------ | ---------- | -------------- |
| `wrist` | 现有腕部位，支架必须**刚性**                     | 640×480@30 | 指尖与方块相对关系、闭合瞬间 |
| `base`  | **独立落地支架**，斜俯视 55–65°，距工作区 80–100 cm | 640×480@30 | 方块/球/袋子绝对位置    |

base 放在机械臂**对面偏 20–30°**，让末端朝远离相机方向下降，减少手臂挡视线。**不要夹桌边**（会被撞、会抖）。对焦环用胶带锁死。

### 4.5 遮挡检查（必做，约 30 分钟）

把红方块放 12 个格点，从臂完整走一遍抓放轨迹，逐格点确认：

- 接近段至少 **60% 的帧**方块被检出
- 抓取瞬间允许短暂遮挡，但闭合前 10 帧内至少一次可靠检出
- **袋子在 5–8 个计划位置都能被检出**

不达标 → 抬高俯角或侧移相机**重装**，不要靠调 HSV 阈值硬补。

### 4.6 采集命令

先确认序列号归属，然后：

```bat
python -X utf8 -m lerobot.nero_tools.episode_capture ^
  --camera-type realsense ^
  --camera-spec wrist=serial:261622078506,size:640x480,fps:30 ^
  --camera-spec base=serial:261622071323,size:640x480,fps:30 ^
  --base-roi 40,60,560,380 ^
  --base-bag-roi 40,60,560,380 ^
  --base-exclude-top 0.03 ^
  --cube-color red --ball-color blue ^
  --leader-channel <主臂通道> --follower-channel <从臂通道> ^
  --leader-firmware v120 --follower-firmware v121 ^
  --leader-gripper-width 0.10 --follower-gripper-width 0.07 ^
  --gripper-force 1.0 --fps 30 ^
  --max-joint-speed 0.6 --max-gripper-speed 3.0 ^
  --max-control-dt 0.1 --episode-seconds 12 ^
  --pose-file examples\nero\saved_start_pose.json ^
  --output outputs\red_cube_300_20261027
```

**注意**：

- `<主臂通道>` `<从臂通道>` 必须换成实测值，**不要套用文档里的历史数字**
- `--base-roi` 的数值要根据实际画面调，先用 `--list` 和预览确认
- 单条时长 **10–12 秒**，不要 20 秒（长尾犹豫帧是噪声且占存储）

### 4.7 采集按键

| 键         | 行为                              |
| --------- | ------------------------------- |
| `S`       | 开始运动并录制                         |
| `E`       | **成功** → 保存，`result=manual_end` |
| `D`       | **失败** → 丢弃                     |
| `R`       | 从臂自动归位，然后**人工把主臂拖回起点**          |
| `Q`/`Esc` | 退出并请求失能                         |

**成功判定（严格执行）**：方块确实在袋内，未抓球、未把球碰进袋、无碰撞、无人工干预。  
**只要不确定就按 D。宁可少一条，不可错一条。**

`R` 之后主臂必须手动拖回——主臂自动回位在这套 SDK 上从未成功过（`set_normal_mode()` 在新档位是空操作）。

### 4.8 分阶段推进（建议）

| 阶段 |      条数 | 门槛                    |
| -- | ------: | --------------------- |
| 试采 |       3 | 双路图正常、袋子框稳定、按键正常      |
| 试点 | 60（A 组） | 无 invalid，抽检 10 条画面正确 |
| 主采 |     220 | 12 格点都覆盖到             |
| 补采 |   40+40 | B 组                   |

**不要一上来就采 300 条。** 先 3 条验证链路，出问题只损失 3 条。

- ⚠️ **该命令的 connect() 会短暂给机械臂通电**（已加告警与自动失能收尾）。执行前两臂必须支撑、夹爪空载、急停可触达
- 若卡在“等待固件回推” → Ctrl+C，检查是否有上位机占用 CAN、适配器是否插好

备用诊断（子进程隔离，避免 cando.dll 崩溃带走整个进程）：

```bat
python -X utf8 tools\diag_can_channels.py
```

## 7. 已知问题与风险

| # | 问题 | 影响 | 对策 |
|---|---|---|---|
| 1 | **通道号未确认** | 主从不分可能两边同时使能 | 每次开机只读重认 |
| 2 | `saved_start_pose.json` 可能已失效 | `--return-to-start` 会大幅搬运 | 核实前禁用该参数；该文件里 leader/follower 曾存同一组值 |
| 3 | 主臂自动回位从未成功 | `R` 只能人工拖回 | 接受此限制 |
| 4 | 主从回位容差 10 度只告警不中止 | 容差内偏差被放过 | 人工观察 |
| 5 | 从臂读失败会沿用缓存 | 可能存陈旧状态 | 训练前审查异常轨迹 |
| 6 | 普通失能清理有 UNCONFIRMED 警告（尤其夹具） | 可能实际仍使能 | 以**推进的反馈时间戳**为证据，否则报 UNCONFIRMED |
| 7 | Ctrl+C/异常时只有 Q/Esc 路径会自动保存片段 | 其他异常可能丢片段 | 正常收尾用 Q/Esc |
| 8 | base 裁剪 `--base-crop` 只记录不裁图 | 有效分辨率未提升 | 如需 320×240 裁剪，须在转换器补一步 |
| 9 | 转换器 shape 断言写死 640×480 | 改分辨率会失败 | 改分辨率须同步改 `convert_episodes.py` |
| 10 | 球坐标已进 env-state，但训练需 env-state dropout | 否则策略过度信任检测器，漏检即崩 | 训练时以 p≈0.15 整组置零 |
| 11 | USB-CAN 适配器插 HUB 会 `cando_frame_send failed` | 打开成功≠链路可用 | 直插主板，不要 HUB |

## 8. 安全红线

- 任何运动/使能/归位前：两臂有可靠支撑、夹爪空载、工作区清空、**实体急停可触达**
- 退出时七关节与夹爪**分别**用推进的反馈时间戳确认失能，否则报 `UNCONFIRMED`
- 网页控制台和 Python 异常退出**不是急停系统**
- 两个 USB-CAN 必须是独立设备，主从通道不能相同
- 不要执行 `move_js`；不要未经确认改夹具固件、零位、最大行程或夹持力
- 程序不是硬实时安全 PLC，不能替代硬件安全回路
- **AI 不自行上电/测试机械臂**，所有上电动作由操作者本人执行

## 9. 术语

| 术语 | 含义 |
|---|---|
| base 视角 | 固定第三视角，管绝对位置与全局上下文 |
| wrist 视角 | 腕部相机，管指尖相对关系；像素坐标**无绝对意义** |
| env-state | 14 维低维物体状态，**只由 base 视角检测器产出** |
| 帧龄 (age) | 当前 tick 与帧采集时刻之差，> 200 ms 判 episode invalid |
| manual_success | 现场人工确认成功，本方案唯一正样本来源 |
| `auto_end` | 到时长自动结束，**不等于成功** |
